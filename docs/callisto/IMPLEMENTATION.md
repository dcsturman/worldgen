# Callisto System Generation — implementation spec for Worldgen

This document tells a coding agent how to implement the Callisto rules in Worldgen. It is derived from
the referee-facing rulebook and contains no rule the rulebook lacks; where the two disagree, **the
rulebook wins** and this file is the one to fix.

- Rulebook text: `docs/callisto/source.md` (exported from the source-of-truth document). Read it first, all of it.
- Every table, machine-readable: `docs/callisto/tables.json` (41 tables, `number`, `title`, `note`, `header`, `rows`, cells as the printed strings).
- The booklet build (`build.py`, `callisto.tex`) is unrelated to the generator and can be ignored for this work.

Status: first implementation. The rulebook is at review stage; expect small table changes. Keep the
tables as data so a change in the rulebook is a change in `tables.json`, not in code.

---

## 1. Goals, principles and the two invariants

Callisto replaces Book 6 star-system generation in Worldgen. Three principles, in priority order:

1. **Playability first.** Charted Space must stay playable as Traveller. Where physics and the setting conflict, the setting wins and the rulebook says so (rulebook Section 13.4).
2. **The rulebook's dice and tables are the algorithm.** The generator rolls the same tables with the same DMs in the same order, so a system generated by hand and one generated by code have the same distribution. Tables that are computed from formulas (Tables 5, 14, 20, 25, 30, 31, 35, 40) may be computed in code, but the code must reproduce the printed values within rounding; keep a test that checks each printed cell against the formula.
3. **Published data always wins.** Constraints passed in are never changed (Section 3 below). Unstated quantities are free.

Two invariants must hold over a large sample of freely generated systems (a test that runs a few thousand systems with fixed seeds):

- **Fuel.** A wilderness fuel source exists in every system with a star (Section 5.6 of the rulebook: every system has ice; the roll decides how convenient). Giant planets are present in 83% ± 2% of systems with `gas_giant_rate = traveller`.
- **Habitable main worlds.** When a main world is generated freely from the Core Rulebook tables, the fraction with atmosphere 4–9 and hydrographics 1+ is about 53%; Callisto must not lower it, because the star and system are built to fit the main world, never the reverse.

## 2. Units and the central change: positions in HD

Book 6 orbit numbers go away. An orbit is placed by **position** in **habitable distances (HD)**: 1 HD is the distance from *that* star at which a world receives Earth's sunlight. Real distance in Mkm = position × the star's `1 HD (Mkm)` (Table 5). Travel time in days at thrust 1 = the star's `Days to 1 HD` × √position (Table 14 gives √position as "Travel ×").

Formulas behind the star table (Table 5), so the code can compute rather than look up, with `L` = luminosity (Sun = 1), `M` = mass (Sun = 1), `R` = radius (Sun = 1):

| Quantity | Formula | Notes |
| --- | --- | --- |
| 1 HD in Mkm | 149.6 × √L | |
| Days to 1 HD | 0.234 × √(1 HD in Mkm) | travel at 1 g, accelerate to midpoint then decelerate: days = 0.234 × √(Mkm); divide by √thrust for higher ratings |
| Jump shadow (Mkm) | 139.2 × R | 100 diameters |
| Innermost orbit (HD) | max(0.05, shadow ÷ 20 ÷ (1 HD in Mkm)) | |
| Lock limit (HD) | 0.4 × M^(1/3) ÷ √L | printed as "all" when ≥ 3 |
| Moon limit | 117 × √L ÷ M^(1/3) | half the Hill radius in planetary radii for an Earth-density planet at 1 HD; Table 30 multiplies by position and rounds to bands |
| World jump limit | size × 160,000 km | |

Stellar parameters by spectral class and subtype (Table 5) come from the Mamajek mean dwarf sequence; use the printed table as data. Other luminosity classes are multipliers on the class V row (Table 6).

Existing `World.orbit_distance_mkm` stays and becomes the primary physical fact; `World.orbit` (slot index) and `position_in_system` remain as the ordering key. See Section 6 on serialization.

## 3. Inputs, constraints and what is free

`system_from_upstream` / `build_constraints` already turn Travellermap data into `SystemConstraints`. Under Callisto the following are **constraints** and are never altered:

- main world UWP (all digits, including the ones the rules would otherwise roll);
- every star in the stellar string (spectral class, subtype, luminosity class) — this includes stars that make the main world physically implausible;
- PBG belt and gas-giant counts; the world count;
- anything in `overrides.json` and any `Constraint` a caller passes.

Everything else is free: orbit positions (except a pinned main-world orbit), other worlds' size/atmosphere/hydro, composition, moons, rotation, tilt, eccentricity, temperature.

**Constraints that cannot be made consistent** (rulebook Section 13.2): generate anyway, honour the constraint, place the main world by Table 10, and record the conflict (Section 7 below). Never move a published world; if a companion star must move to make a habitable zone stable (Table 8 check), move the companion and record it. A listed star that cannot host the main world (white dwarf, giant): if a class V companion exists the main world orbits the companion (Section 3.5 of the rulebook); otherwise generate around the listed star and record `strained`.

Orbit-number inputs still arrive from two places and need converting once: `overrides.json` entries that place bodies by orbit number, and `SystemConstraints.main_world_orbit`. Provide a conversion using the Book 6 orbit-number → AU table (orbit n AU: 0.2, 0.4, 0.7, 1.0, 1.6, 2.8, 5.2, 10, 19.6, 38.8, 77.2, 154, 307, 615, 1230, 2500, 4900, 9800, 19600, 39500), then Mkm = AU × 149.6, then HD = Mkm ÷ (1 HD in Mkm). Migrate `overrides.json` to Mkm (or HD) in one pass and keep the reader tolerant of both for one release.

## 4. The generation procedure, step by step

Follow rulebook Section 2 (Table 1) in order. Each step names the rulebook table; the code must use the table's rows and DMs as printed.

1. **Stars** (Sections 3.1–3.3, Tables 2–4). Skip when listed. Habitable main world ⇒ "habitable" column of Table 3 and class V without a roll.
2. **Star data** (Table 5, Table 6 multipliers).
3. **Companions** (Section 3.5, Tables 7–9). Mass ratio → nearest Table 5 row by mass. Separation in the primary's HD; gap = [sep/3, 3×sep]. Habitable-zone check: if 1.0 is in the gap and the system has a habitable main world, move the companion (1D 1–3 inward, 4–6 outward) row by row until clear; record the move. Third star per Table 9. A companion's own worlds: generated with its own Table 5 row, kept only inside sep/3 (compare in Mkm).
4. **Main world position** (Section 4.1, Table 10) from atmosphere/hydro bands; 1D spreads the band. A pinned distance (override or `main_world_orbit`, converted to HD) wins.
5. **Number of orbits** (Section 4.2): 2D − 2, minimum 1, and at least the known body count (belts + giants + planets + main world). No DM for star mass.
6. **Orbit positions** (Sections 4.3–4.4, Tables 11–12). Without a main world: Table 11 for orbit 1, then multiply by Table 12 ratios. With a main world: split remaining orbits inward/outward by 1D (1–2: one third inward, 3–4: half, 5–6: two thirds, floor), divide inward, multiply outward. Round to two significant figures. Enforce the innermost-orbit limit (Table 5). Cross out positions inside a companion gap; they do not count toward the orbit total; keep multiplying from them. Stop at position 100. For a known body count, keep rolling further orbits until enough stable ones exist.
7. **Zones** (Table 13) from position: Inner < 0.5, Hot 0.5–0.95, Temperate 0.95–1.7, Cold 1.7–2.7, Outer ≥ 2.7.
8. **Giant planets** (Section 5, Tables 15–18). Presence 2D ≤ 9 (or ≤ 7 with `gas_giant_rate = physical`); a known count skips the roll. Number by Table 16. Kind by Table 17 (ice giant 2–7, gas giant 8–12; gas giant size 1D: 1–4 Saturn-class, 5–6 Jupiter-class). Placement by Table 18 with the rules in Section 5.4: first free Outer / Cold / migrated; later giants take the next free Cold or Outer orbit outward; if none is free, **add an orbit** at max(2.7, 1.75 × outermost) — for every giant when the count is known, at most one added orbit when the count was rolled. A Temperate-zone giant displaces the world there.
9. **Ice** (Section 5.5, Table 19, 2D): 2–3 uncharted/sparse; 4–9 charted belt in the outermost orbit beyond the last giant (or the giant's moons if none); 10+ rich. Mark ice sources: ice-rock worlds in Cold/Outer, worlds with hydro ≥ 1 in Cold/Outer, moons of outer giants.
10. **Refuelling line** (Section 5.6): `transit_fuel` ∈ {GiantPlanet, ChartedIce, UnchartedIce} (best available; never None for a system with a star) and `local_fuel_days` = the star's days-to-1-HD × √(max(position of nearest source, position of main world)); classify < 7 convenient, < 21 reachable, else not reachable.
11. **Fill orbits** (Section 6, Table 21 by zone; DM −1 if primary mass < 0.3; DM +1 next to a giant when the result would be Belt). Body kinds: Empty, Belt, World, Sub-Neptune, Icy dwarf (Table 22 gives fixed codes for the non-World kinds). Orbits inside a hot Jupiter's orbit are Empty.
12. **Worlds** (Section 7): size 2D − 2 (DM −2 Inner, −1 primary mass < 0.3, min 1); composition 1D (≤1 iron-rich, 2–4 rocky, ≥5 ice-rock; DM −2 Inner/Hot, −1 Temperate, +1 Cold, +2 Outer); gravity = size/8 × density (0.6 / 1.0 / 1.3) — Table 23; atmosphere 2D − 7 + size with DMs (+1 iron-rich, −1 ice-rock, −2 Inner, −1 Outer, −2 size 2; size 1 ⇒ 0; clamp 0–15); hydrographics 2D − 7 + size with DMs (−4 if atmo ≤ 1 or ≥ 10; −2 Hot; size 1 or Inner ⇒ 0; clamp 0–10; Cold/Outer ⇒ ice flag). A known main world keeps its UWP; only composition and temperature are computed.
13. **Temperature** (Section 7.5, Tables 24–27). Albedo class from Table 24; equilibrium °C = 278.5 × (1 − A)^¼ ÷ √position − 273.15 (Table 25 is this formula tabulated); add greenhouse by atmosphere (Table 26: 0–1: 0, 2–3: 5, 4–5: 20, 6–7: 35, 8–9: 60, A: 50, B: 150, C: 250, D: 100, E: 10, F: 35); bands (Table 27): Frozen ≤ −51, Cold ≤ 0, Temperate ≤ 30, Hot ≤ 80, Roasting. Ice check: if Cold/Frozen with hydro ≥ 1 and not already Ice class → recompute once with albedo 0.65. Roasting with hydro ≥ 1 → Cloudy, stays Roasting. Also compute the world's mean temperature in °C for the map (a computed extra; the rulebook works in bands).
14. **Moons** (Section 8, Tables 28–31): counts and rings by body kind; moon size for worlds by 1D (1–3 S, 4–5 size 1 or S if parent ≤ 3, 6 large = parent ÷ 3 floor, min 1); giants 2D − 6 (min S); a giant in the Temperate zone rolls its first moon at 2D − 3 (min 1) and that moon is generated as a world at the giant's position with composition DM +1. Large moon = the "6" result. Orbits by band (Table 29) in planetary radii; stability by Table 30 (rows = star's moon limit, columns = position; giants read one row up); moons beyond the cap move to the cap; cap < 3 ⇒ no moons. Rings: size code R, 1.5–3 radii. Moon period (Table 31): hours = 1.41 × r^1.5 × √(size ÷ 8 ÷ gravity); every moon of size S+ is locked to its planet (rotation state `PlanetLocked`, day = period). Tidal heating: Close-band moon of a giant reads one band warmer if Cold/Frozen; size ≥ 3 ⇒ `volcanic` flag.
15. **Eccentricity, rotation, tilt, year** (Section 9, Tables 32–35). Eccentricity 2D (DM −2 at/below lock limit, +1 companion inside 20 HD); if ≥ 0.2 evaluate the band at position × (1 ± e) and if the bands differ set `two_season` with both bands. Rotation: below lock limit ⇒ `StarLocked`, or `Resonance32` if eccentricity ≥ 0.15; above ⇒ free, day from Table 32 (DM +2 large moon; 12 ⇒ 1D × 100 h, retrograde on 1D 1–2). **Main world exception:** never apply StarLocked/Resonance to the main world automatically; compute it, store it as `physics_rotation`, and apply only an explicit decoration (Section 5 below). Tilt Table 33 (DM −2 large moon, −2 at/below lock limit; locked worlds have no meaningful tilt). Year in days = 0.2 × d_Mkm^1.5 ÷ √M.
16. **Settlement of other worlds** (Section 10, Tables 36–39): population 2D − 2 with Table 36 DMs (surface rows for worlds and moons; the belt row instead for belts; the "every body" rows for all), capped at main world population − 1, floor 0; government (Table 37 with the pop 1–2 rule); law 1D − 3 + main law (0 if gov 0); facilities (Table 38, including Fuel depot and the "remarkable" research DM); tech level (main − 1; = main with lab/military; ≥ 7 when life support is needed); spaceport 1D (Table 39). Main world population 0 or main TL ≤ 6 ⇒ every other body population 0. No main world ⇒ population 0 everywhere.

Random numbers: use the system seed as today (`seed::system_seed`) so a system regenerates identically; roll in the order above so seeds stay stable across small table edits.

## 5. Data model changes (Rust)

Keep every change additive and serde-compatible (see Section 6). Suggested shapes; names are free.

- `Star`: unchanged classification. Add a derived `StarData { luminosity, mass, radius, hd_mkm, days_to_hd, jump_shadow_mkm, innermost_hd, lock_limit_hd, moon_limit }` computed from Table 5/6 (a function, not stored).
- `System`: `orbit_slots: Vec<Option<OrbitContent>>` stays as the ordered container; add per-slot `position_hd: f32` and `distance_mkm: f32` (or a small `Orbit { position_hd, zone, content }`). Companion separation in HD (and Mkm) on the companion `System`; keep `StarOrbit` for callers but stop using orbit numbers as physics.
- `OrbitContent`: add `SubNeptune(World)` (or a `WorldClass` on `World`), `IcyDwarf`, `Belt` distinct from `World` if it is not already; `GasGiant` gains `kind: GiantKind { IceGiant, SaturnClass, JupiterClass }` (extend `GasGiantSize` rather than replace it if the UI depends on it).
- `World`: add `composition: Composition { IronRich, Rocky, IceRock }`, `gravity: f32`, `temperature_c: f32`, `temperature_band: TempBand`, `ice: bool` (hydro is ice), `is_ice_source: bool`, `eccentricity: f32`, `axial_tilt_deg: f32`, `rotation: RotationState { Free { hours, retrograde }, StarLocked, Resonance32, PlanetLocked { hours } }`, `physics_rotation: RotationState` (what the physics said, before the main-world exception), `two_season: Option<(TempBand, TempBand)>`, `volcanic: bool`, `year_days: f32`, `fit: Fit` (Section 7).
- Moons: satellites are `World`s already; add `orbit_radii: f32`, `band: MoonBand`, `is_large: bool`, `is_ring: bool` (size code R).
- Refuelling: `System` gains `transit_fuel: TransitFuel`, `local_fuel_days: Option<f32>`, `ice: IceAvailability { Uncharted, Charted, Rich }`.
- Settings: `GenerationSettings { gas_giant_rate: GasGiantRate }` with `GasGiantRate::{Traveller, Physical}`; absence means `Traveller`.
- `WorldDecorations`: keep `tide_locked: Option<TideLock>`; add a tri-state override `rotation_override: Option<RotationOverride { Locked(TideLock), NotLocked }>` usable on any body. Semantics: main world ⇒ only an explicit `Locked` produces a locked map; other planets ⇒ physics applies unless `NotLocked`; moons ⇒ always `PlanetLocked`, never `StarLocked`. The generator must know which body is the main world (`is_mainworld` already exists).
- Map-side decorations to emit for every world (the map generator consumes them; the rulebook calls them computed extras): rotation state and day length, mean temperature and hydrosphere phase (liquid / ice / steam), axial tilt, eccentricity and two-season flag, gravity, atmosphere code, star colour (from Table 5 temperature), tectonic activity (volcanic flag), large moon or ring present. A two-season world gets **two maps**, one per end of the year.

## 6. Serialization and compatibility

`World` is deserialized from stored Firestore documents and `TradeState` messages written before any of this existed. Every new field must be `#[serde(default)]` and skipped when empty/default so untouched documents round-trip byte-identically (the pattern `decorations` and `orbit_distance_mkm` already use). Do not rename or remove existing fields. Old documents will have no `position_hd`; derive it from `orbit_distance_mkm` when present, else leave unset and fall back to the slot order for drawing.

---

## 7. Fit, review file and reporting

Every generated world carries `fit`:

- `Exact`: nothing adjusted.
- `Tuned`: only unstated quantities were set (the normal case).
- `Adjusted { what, why }`: an unconstrained star or orbit was chosen to suit the world, or a companion was moved.
- `Strained { story }`: a constraint forced a physically unviable result.

`Strained` entries are written to a **review file**, not a log: `docs/callisto/review/<sector>.md` (or JSON), one entry per world and conflict kind, keyed by sector and hex, **replaced on rerun** rather than appended. Each entry: world name and hex, the constraint honoured, what physics expected, the story the generator settled on. This is the file the maintainer opens to find bad published data.

The existing `DroppedConstraint` mechanism stays for constraints that could not be placed at all.

---

## 8. Tables that are formulas (test these)

For each of Tables 5, 14, 20, 25, 30, 31, 35, 40, write a unit test that recomputes every printed cell from the formula in Section 2 or Section 4 above and asserts equality within the table's rounding (two significant figures for positions; whole degrees for Table 25; one decimal for days under 10, whole days above). If a cell fails, the rulebook is wrong and should be fixed there first.

Tables that are pure dice lookups (2, 3, 4, 7, 8, 9, 10, 11, 12, 13, 15–19, 21–24, 26–29, 32–34, 36–39) are loaded from `tables.json` at build time; a test asserts each 2D table covers 2..12 with no gaps and each 1D table covers 1..6.

## 9. System map (sysmap) changes

- Draw orbits at their positions (log scale is fine), not at Book 6 slots; label distances in Mkm and travel days.
- Distinct icons or colours per body kind: iron-rich / rocky / ice-rock world, belt, sub-Neptune, icy dwarf, ice giant, Saturn-class and Jupiter-class gas giant, ring (R), crossed-out companion gap.
- Show the refuelling line (transit fuel kind, local fuel days) in the legend, and mark ice sources.
- Mark two-season and volcanic worlds.

## 10. Acceptance

- The three worked examples in rulebook Section 12 are reproduced structurally (same steps, same tables) when their rolls are supplied; a deterministic "scripted dice" test harness that feeds the listed rolls should produce the listed systems (allowing for the Section 12 text being written before the last table edits — fix the examples, not the code, where they differ).
- The two invariants in Section 1 hold over a seeded run of 5,000 free systems.
- Regenerating the Trojan Reach from Travellermap data produces no `DroppedConstraint`s for systems that had none before, and the review file lists every `Strained` world.
- Existing stored worlds still deserialize and render unchanged.

## 11. Out of scope for the first implementation

Population/government/law/TL of the main world (Core Rulebook, unchanged); the booklet build; the referee worksheet; the HTML edition of the rulebook.
